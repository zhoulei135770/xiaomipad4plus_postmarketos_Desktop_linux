## 3. 当前显示方案（重要，别改回去）

**X 使用 fbdev 驱动，不是 modesetting。**

```
/etc/X11/xorg.conf.d/20-fbdev.conf        ← 生效
    Driver "fbdev", Option "fbdev" "/dev/fb0"

50-msm-soft.conf.disabled                 ← 已停用
20-gpu.conf.{disabled,broken,bad-present}  ← 已停用
```

原因见 [47-FBDEV-DISPLAY-PATH.md](47-FBDEV-DISPLAY-PATH.md)：modesetting 路径下
X 的渲染结果永远不进扫描缓冲（黑屏只剩光标），而这台设备的面板本身完全正常
（直接写 `/dev/fb0` 能显示）。

**代价**：fbdev 不支持 RandR 旋转 ⇒ **固定竖屏 1200×1920**，无法横屏。

`lxqt-x-session` 里的开机旋转行已替换为 `true`（否则每次开机必黑屏）。

## 4. 当前遗留问题（按优先级）

### P0 — 横屏不可用

- 现状：竖屏 1200×1920 固定
- 原因：fbdev 驱动无 RandR 旋转支持
- 可行方向：
  1. **应用层旋转**（推荐）：让桌面在竖屏 X 里以旋转后的坐标布局
  2. 继续修 modesetting 路径：现在已证明面板没问题，问题在 X 的输出环节
  3. 换别的显示栈（实验性）

### P1 — GPU 不可用

- `adreno_zap_shader_load` 失败：`Unable to load a512_zap.mdt`
- 结果：`gpu hw init failed: -2`，所有渲染走 llvmpipe
- 影响：横屏（若恢复）和视频播放会很吃 CPU
- 待查：`/lib/firmware/qcom/a512_zap.mdt` 是否存在、是否需要 devicetree 里的 zap-shader 节点

### P2 — 前摄像头

- 后摄：已验证出图（BGGR，`mipad4plus/43-CAMERA-PIPELINE.md` §7.6）
- 前摄：所有 I²C 地址 NACK → 需要**拆机检查模块与排线**（电气路径已确认没问题）

### P3 — 调制解调器 / GPS

- 无 modem 设备节点；GNSS 无 `/dev/gnss*`
- adsp/cdsp 在跑，说明固件加载正常，可能是 DT 里缺 modem/GNSS 节点
- 不能盲试，需要上游设备树参考

### P4 — 指纹

- fpc1020 只暴露成输入设备，没有 `/dev/fpc*`
- 若要可用需要 fpc1020 驱动以字符设备模式工作 + fprintd 后端

### P5 — 桌面观感

- 桌面快捷方式上有黑色感叹号（pcmanfm 认为 `.desktop` 不可信）
- 需要 `gvfsd-metadata` 才能真正标记 trusted，但该服务起不来
- 纯观感，不影响功能

## 6. 如果又黑屏了怎么办

按顺序试：

1. **长按电源键彻底关机**，再开机
2. SSH 进来执行：
   ```sh
   echo 0 > /sys/class/graphics/fb0/blank
   systemctl restart greetd
   ```
3. 确认 X 用的是 fbdev：
   ```sh
   grep 'Device "fbdev"' /var/log/Xorg.0.log
   ```
4. 若被人改回 modesetting，把 `20-fbdev.conf` 重新启用、其余配置改名 `.disabled`

**判断口诀**：截图有内容但屏幕黑 ⇒ 问题在 X 输出路径，不是面板。
