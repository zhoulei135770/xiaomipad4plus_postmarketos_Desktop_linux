### 1.5 显示：fbdev 竖屏稳定；`Option "Rotate"` 失败原因已定位
- 实测 `20-fbdev.conf` 加 `Option "Rotate" "CCW"` 后 X 启动失败：
  ```
  (EE) FBDEV(0): FBIOPUT_VSCREENINFO: Invalid argument
  (EE) FBDEV(0): mode initialization failed
  ```
- 读源码定位到根因：`xf86-video-fbdev` 在 ScreenInit 里先把 `virtualX/Y` 转置
  （1200x1920 → 1920x1200），之后服务器再调用 `SwitchMode` 时，
  `fbdevHWSetMode()` 用转置后的尺寸算 `xres_virtual/yres_virtual`，
  得到 `yres_virtual(1200) < yres(1920)`，DRM fbdev 直接 EINVAL。
- **补丁已写好**（见 §2），思路：模式设置时临时把尺寸换回面板的 1200x1920，
  设完再换回旋转后的 1920x1200；X 屏幕仍是 1920x1200，ShadowFB 负责旋转。

### 1.6 一个重要的坑：tablet-autorotate 会主动重启整机
- `/usr/local/bin/tablet-autorotate` 在检测到 modeset wedge 时，30 分钟内第 3 次会
  `systemctl reboot`。
- 我今天重启 greetd 测试旋转时，它把这个当成 wedge，**直接把设备重启了**
  （journal 里 08:19:36 是干净的 `systemctl reboot`）。
- 以后任何改显示/重启 X 的实验，必须先
  `systemctl stop tablet-autorotate tablet-touch-rotate`，结束再启回来。
- 长任务必须用 `systemd-run --unit=...` 跑，普通 SSH 会话被杀时 `setsid` 也救不了
  （systemd 会清整个 session cgroup）。

---

### 1.7 重要教训：SSH 探测本身会把 sshd 打到 MaxStartups
- 设备卡住时我连续快速尝试了几十次 SSH，sshd 的未认证连接槽被占满，
  之后新连接会收到 `Not allowed at this time`，看起来和"整机卡死"一模一样。
- 以后排障规则：
  1. 两次 SSH 尝试之间至少等 **120 s**（LoginGraceTime 默认值）；
  2. 一次只开一个连接，拿到结果再决定下一步；
  3. 判断"真死"要看 `ping` + 单个连接的 banner，不要用并发扫描。

### 1.8 真卡死的判据（目前最可靠）
- `ping` 通 + TCP 22 能握手 + **120 s 后单连接仍无 banner** → 内核/IO 卡住。
- 此时只能**长按电源 10–15 s 彻底断电**；`systemctl reboot`（温重启）不一定能清掉
  GPU/NoC 的挂死状态。

## 2. 已准备好的横屏方案（等设备回来即可执行）

**已在 VM 上实机验证（2026-10-30 09:1x）**：Ubuntu VM 的 /dev/fb0（vmwgfx，固定模式）
装上打完补丁的驱动 + `Rotate "CCW"`，X 正常启动，屏幕变成 600x800（由 800x600 转置），
抓 `/dev/fb0` 与 `xwd` 的根窗口逐像素对比：**与 CCW 旋转完全一致（平均差 0.13/255）**，
说明补丁、ShadowFB 旋转、stride（4704）处理都是对的。

由这次对比也确认了触摸映射：`Rotate CCW` 时 screen=(1-v, u)，
所以 `LIBINPUT_CALIBRATION_MATRIX="0 -1 1 1 0 0"`。

目录：`mipad4plus/patches/fbdev-rotate/`

| 文件 | 用途 |
|---|---|
| `fbdev.c` | 打完补丁的 xf86-video-fbdev 0.5.0 源码 |
| `xf86-video-fbdev-0.5.0-portrait-rotate.patch` | 对应 unified diff |
| `build-on-device.sh` | 在设备上装 build-base/xorg-server-dev 并编译出 `fbdev_drv.so` |
| `deploy-landscape.sh` | 备份→安装→写 `Rotate CCW`→重启 greetd→验证→失败自动回滚 |

验证判据（脚本里已实现）：`xrandr --query` 出现 `1920x1200` 且 fb 抓图非黑；
不满足就还原驱动与配置并重启 greetd。

触摸：用 udev 属性（不是 XInput CTM，那个是只读的）：
```
ATTRS{name}=="Goodix Capacitive TouchScreen", ENV{LIBINPUT_CALIBRATION_MATRIX}="0 -1 1 1 0 0"
```
这是 `Rotate CCW` 对应的 `(1-v, u)` 映射；如果实际方向相反，改成 `"0 1 0 -1 0 1"`。

回滚：
```
cp /root/fbdev_drv.so.orig /usr/lib/xorg/modules/drivers/fbdev_drv.so
cp /root/20-fbdev.conf.orig /etc/X11/xorg.conf.d/20-fbdev.conf
systemctl restart greetd
```
