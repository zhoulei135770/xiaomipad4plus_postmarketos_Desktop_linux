## 3. IPA / TZ：确认不可用（并发现一个上游 bug）

### 3.1 IPA 寄存器不可访问

所有软件手段逐一排除（时钟 75 MHz、ICC 三路径 INT_MAX、SMMU 时钟、固件、驱动流程、直接读写）：

**任何对 `0x14780000` 的访问都会让 CPU 停住。**

### 3.2 TZ 的 MP 服务对 APPS 不开放（决定性对照实验）

```
qcom_scm_is_call_available(svc, cmd):
  (0x0c, 0x10) → 0     ← 原厂 IPA 解锁命令不存在
  (0x0a, 0x01) → 1     ← PIL 服务存在（对照组，证明查询机制正常）
```

⇒ 原厂的 `ipa3_tz_unlock_reg()` 在本机同样会失败；**XPU 不是我们能在 Linux 侧解开的**。

### 3.3 发现上游 bug：IPA 核心时钟速率从未生效

`ipa_power_init()` 在时钟**未使能**时调 `clk_set_rate()`，而 `clk_smd_rpm_set_rate()`
在 `!r->enabled` 时直接返回 → 速率被丢弃。

- 证据：同一设备，原顺序 `clk_get_rate()` = `2147483647`；改成 enable→set_rate 后 = `75000000`；
- 已产出可提交补丁：[patches/0001-net-ipa-apply-core-clock-rate-after-enable.patch](patches/0001-net-ipa-apply-core-clock-rate-after-enable.patch)；
- 详见 [64-UPSTREAM-IPA-REPORT.md](64-UPSTREAM-IPA-REPORT.md)。

## 4. GPS / QMI：**重要更正——QMI 节点是 0，不是 1**

```
qmicli -d qrtr://0 --dms-get-ids        → IMEI 868225041565635  ✅
qmicli -d qrtr://0 --loc-get-operation-mode → standalone        ✅
qmicli -d qrtr://0 --loc-start          → session 0             ✅
qmicli -d qrtr://0 --loc-get-position-report → timeout          ❌（从未拿到过坐标）
```

- 之前误用 `qrtr://1` 导致"全部 Internal"的错误结论，已在 [65-GPS-QMI-FINDINGS.md](65-GPS-QMI-FINDINGS.md) 更正；
- GPS **服务层是通的**，但**从未真正定位成功**（室内/窗边各测 200s、150s 均无输出）；
- 真正测定位需要 modem online，而 modem online **约 3 分钟必崩**（见 §6）→ GPS 目前不可实用。

## 5. 相机

### 5.1 后摄偏色（橙→绿）= Bayer 相位

- 这颗 OV13855 实测是 **BGGR**，而 GUI 里旧代码按 **GRBG** 取平面 → R/B 互换；
- 已修 `/usr/local/bin/tablet-camera-gui`（备份 `.bak-grbg-1410`），CLI 路径 `develop.py` 本来就是 BGGR；
- 实测成片：橙色盒子恢复橙色 ✅（见 [43-CAMERA-PIPELINE.md](43-CAMERA-PIPELINE.md) §7.7）。

### 5.2 系统默认相机（GNOME Snapshot / libcamera）

- 用 `SGRBG10`（驱动当前上报）→ 颜色偏绿；
- 把驱动改成正确的 `SBGGR10` → **libcamera 反复重试、画面闪烁** → 已回滚；
- 结论：libcamera 对 qcom-camss 纯 RAW 的支持不完整，**默认相机在这台机器上不可用**，请用「平板相机」。

## 6. SIM / 蜂窝：换卡后可用，但不能长开

- **旧 SIM 卡坏了**：同位置、同机器 `Card state: 'error: no-atr-received (3)'`；
- **换新卡后**：`Card state: 'present'` → **注册 CMCC**，LTE `RSSI -62 dBm / RSRP -90 dBm / SNR 13.8 dB`；
- 但 modem 设为 online 后约 3 分钟：

```
qcom-q6v5-mss: fatal error: ipa_util.c:1089 IPA Assert
ath10k_snoc: firmware crashed!（每 6 秒一次）
ath10k: failed to enable wcn3990: -22   → WiFi 彻底掉线
```

- 恢复：`modprobe -r ath10k_snoc && modprobe ath10k_snoc`（已验证有效）或重启；
- 已装 `/usr/local/bin/cellular-on.sh`（切 online 并打印状态，附警告）。

## 7. 前摄：软件侧穷尽，仍 `-6 ENXIO`

今天新做的实验（全部失败）：

| 实验 | 依据 | 结果 |
|---|---|---|
| reset 52 → **47** | 原厂 pinctrl 用 gpio47 | 仍 -6 |
| VANA 改用共用 `cam_avdd_2v8`（GPIO51） | 原厂前后摄共用 VANA | 仍 -6 |
| 加 `standby-gpios`（GPIO44） | 原厂 pinctrl 配了 gpio44 | 驱动不支持该属性，无效果 |
| 手动拉 GPIO44 | 绕开驱动 | 引脚被后摄驱动占用（-517） |

⇒ 硬件在 Android 下正常，Linux 侧已无更多可试。详见 [26-FRONT-CAMERA-DIAGNOSIS.md](26-FRONT-CAMERA-DIAGNOSIS.md) §19。

## 8. 指纹：能控制芯片，但功能在闭源 TA 里

- 模块加载、`FPC1020 ready (irq=151)`、输入设备存在；

## 9. 今天踩的坑（重要教训）

1. **不要 `--dms-set-operating-mode=offline`**：这台机器 modem 回不到 online（`InvalidTransition`），
   且关机时 `port failed halt` → **整个关机流程挂死**（黑屏+鼠标）；
2. **不要用 `remoteproc` 重启 modem**：会连带杀掉 WiFi（wcn3990 依赖 modem QMI）；
3. **modem online 最多撑约 3 分钟**，之后 IPA 断言崩溃并带崩 WiFi；
4. `qmicli` 的 QRTR 节点是 **0**（`qrtr://0`），不是 1；
5. 写设备端脚本**必须用 LF**（PowerShell `Set-Content` 的 CRLF 会让 `tail -n 45` 之类命令失败）。
